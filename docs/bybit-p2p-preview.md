# Bybit P2P integration — isolated Preview

This feature branch is deliberately isolated from `main`.

## Runtime guard

All four Bybit API routes return HTTP 404 unless `VERCEL_ENV=preview`. This is a second safeguard in addition to the branch-specific Vercel variables.

## Data isolation

The Preview integration uses these Firestore paths only:

- `users/{uid}/previewIntegrations/bybitP2P` — encrypted API credentials and sync cursor/state.
- `users/{uid}/previewIntegrations/bybitP2PConnectGuard` — connection attempt throttle.
- `users/{uid}/previewOperations` — imported test operations.

It reads `users/{uid}/sessions` to attach a completed order to a unique matching session. It never writes to `users/{uid}/operations`, the Binance integration document, or the existing Cloudflare Worker state.

The Preview build merges `previewOperations` into History, Dashboard, Operations and Arbitrage Sessions only when `REACT_APP_BYBIT_P2P_PREVIEW_MODE=true`. Editing and deleting a Bybit Preview row continues to use the isolated collection.

## Credentials and API scope

- System-generated Bybit API keys using HMAC-SHA256 are supported.
- Enable the P2P read-only permission only.
- The server encrypts the key pair with the Preview-only `BYBIT_P2P_ENCRYPTION_KEY` using AES-256-GCM.
- No create-order, payment, release, transfer or withdrawal endpoint is called.
- Current first-stage endpoint is Bybit Global: `https://api.bybit.com/v5/p2p/order/simplifyList`.
- The API host can be changed only through the server-side `BYBIT_P2P_API_BASE_URL` variable and must match the allowlist in `lib/bybit-p2p.js`.

## Mapping

Bybit returns finished orders with status `50`. The response's `side` maps `0` to Compra and `1` to Venta. In the documented example, `amount` is the fiat total, `price` is fiat per token, and `notifyTokenQuantity` is the crypto quantity. The connector stores those separately.

The Bybit order-list schema does not specify the fee currency. The raw fee is retained as `sourceFee`, while `fee` remains zero until its denomination is validated, so an unknown unit cannot silently distort JJXCAPITAL's profit calculations.

## Synchronization

The Preview currently supports manual sync and bounded pagination (two pages per request, 30 rows per page). The initial backfill covers the 30 days ending at the connection timestamp (a rolling 30-day period, not the previous calendar month). A one-time backfill version migration reopens this 30-day import for existing Preview connections, even if an earlier zero-result sync marked the initial backfill complete; the user does not need to reconnect the API. Further syncs are incremental. A deterministic document ID plus an order lookup prevents duplicates.

The production Cloudflare Worker is intentionally unchanged. Automatic Bybit scheduling is a later step after the real API connection and import mapping have been validated in Preview.

## Vercel environment variables

These variables are configured only for the Preview target and the branch `feat/bybit-p2p-preview-isolated`:

- `BYBIT_P2P_ENCRYPTION_KEY` — encrypted AES-256 key.
- `REACT_APP_BYBIT_P2P_PREVIEW_MODE` — plain value `true`, activates the test card and test-history view.

Do not copy either setting to Production until a separate release and migration plan is approved.

# Bybit P2P integration — Preview and Production

The feature is developed on feat/bybit-p2p-preview-isolated and remains behind the open draft PR until Preview validation is complete. The runtime selects a separate integration and operations path based on VERCEL_ENV.

## Environment isolation

| Environment | Connection and sync state | Imported operations |
| --- | --- | --- |
| Vercel Preview | users/{uid}/previewIntegrations/bybitP2P | users/{uid}/previewOperations |
| Vercel Production | users/{uid}/privateIntegrations/bybitP2P | users/{uid}/operations |

The connection-attempt guard follows the same environment split. Preview financial screens load sanitized Bybit records through the authenticated server endpoint when REACT_APP_BYBIT_P2P_PREVIEW_MODE=true; they do not read the protected Preview collection directly. Preview records are read-only in History. Production Bybit operations use the same operations collection as Binance, so Dashboard, Operations, History, Arbitrage Sessions and profile counters use the normal application paths.

The connector reads users/{uid}/sessions for unique pair-and-time session matching. It does not modify Binance integration documents, Binance operations, Firestore rules or the existing Cloudflare Binance Worker.

## Automatic synchronization

- The Profile card offers manual connect, status, sync and disconnect.
- The authenticated app performs a best-effort background sync every five minutes while a user is active.
- The existing protected GitHub Actions workflow also runs every five minutes. It processes Binance and Bybit batches using the same short-lived GitHub Actions OIDC identity; the Bybit scheduler maintains its own lock and cursor.
- The existing Cloudflare Worker remains Binance-only and is not changed by this integration.

## Credentials and API scope

- System-generated Bybit HMAC-SHA256 API keys are supported.
- Enable only the P2P read-only permission.
- Credentials are encrypted on the server using AES-256-GCM and BYBIT_P2P_ENCRYPTION_KEY.
- Preview and Production must have separate, independently generated BYBIT_P2P_ENCRYPTION_KEY values. The Production value must be configured in Vercel before enabling Bybit in Production.
- No create-order, payment, release, transfer or withdrawal endpoint is called.
- Current endpoint: https://api.bybit.com/v5/p2p/order/simplifyList.
- The API host can be changed only through server-side BYBIT_P2P_API_BASE_URL and must match the allowlist in lib/bybit-p2p.js.

When this branch is eventually released, the user must connect Bybit again in Production. Preview credentials and Preview operations are intentionally not migrated or copied into Production.

## Order mapping and safeguards

Bybit completed orders use status 50. side maps 0 to Compra and 1 to Venta. amount is the fiat total, price is fiat per token, and notifyTokenQuantity is the crypto quantity. These values are stored separately.

The Bybit order-list schema does not identify the fee currency. The raw fee is retained as sourceFee, while fee=0 and fee_currency=null prevent an unverified fee from distorting calculated results.

Initial history recovery covers the 30 days ending at connection time. The sync uses deterministic document IDs and order-ID duplicate checks. It processes at most two 30-row pages per request and resumes from its saved page cursor. Session matching requires the same crypto/fiat pair and an order timestamp within a unique session's active interval. Orders without a compatible session remain imported but unlinked.

## Validation and release status

The integration is still in the Preview/draft-PR phase. Do not merge or deploy to Production until the imported records, financial calculations, automatic schedule and Production encryption variable have been verified. No Firestore rules deployment is required for the Preview viewer or server-side import.

# Bybit P2P integration — Preview and Production

Bybit P2P is integrated in the main application. Preview and Production use separate connection, credential and operation paths based on VERCEL_ENV.

## Environment isolation

| Environment | Connection and sync state | Imported operations |
| --- | --- | --- |
| Vercel Preview | users/{uid}/previewIntegrations/bybitP2P | users/{uid}/previewOperations |
| Vercel Production | users/{uid}/privateIntegrations/bybitP2P | users/{uid}/operations |

The connection-attempt guard follows the same environment split. Preview financial screens load sanitized Bybit records through the authenticated server endpoint when REACT_APP_BYBIT_P2P_PREVIEW_MODE=true; they do not read the protected Preview collection directly. Preview records are read-only in History. Production Bybit operations use the same operations collection as Binance, so Dashboard, Operations, History, Arbitrage Sessions and profile counters use the normal application paths.

The connector reads users/{uid}/sessions for unique pair-and-time session matching. It does not modify Binance integration documents, Binance operations or Firestore rules.

## Import window and duplicate protection

- The first import starts at the exact connectedAt timestamp saved after Bybit credentials are successfully verified.
- Orders created before connectedAt are excluded, including for existing version-2 connections when they are migrated to version 3.
- The first synchronization captures a fixed end timestamp and continues paginated results from its saved page cursor.
- Subsequent synchronizations use lastSyncAt with a short overlap, bounded by connectedAt and Bybit's supported 180-day query window.
- Completed orders only (status 50) are imported.
- Deterministic document IDs and order-ID checks prevent duplicate imports.
- Session matching requires the same crypto/fiat pair and an order timestamp within a unique session's active interval. Orders without a compatible session remain imported but unlinked.

Existing imported operation documents are not deleted automatically when the connection cutoff is changed. The new cutoff governs the initial and future synchronization windows.

## Automatic synchronization

- The Profile card offers manual connect, status, sync and disconnect.
- The authenticated app performs a best-effort background sync while a user is active.
- The existing protected GitHub Actions workflow runs every five minutes as a backup for Binance and Bybit using the same short-lived GitHub Actions OIDC identity.
- The existing Cloudflare Worker `jjxcapital-binance-p2p-sync` handles both providers every minute. It sends Binance to the original endpoint and Bybit to the same endpoint with `?provider=bybit`.
- Cloudflare uses separate secrets: BINANCE_P2P_SCHEDULER_SECRET and BYBIT_P2P_SCHEDULER_SECRET. Each must match its corresponding sensitive Production environment variable in Vercel.
- The Bybit backend maintains its own Firestore scheduler lock and cursor under systemJobs/bybitP2PBackgroundSync.

See cloudflare/README.md for updating and deploying the existing Worker. The Worker contains no exchange API credentials; only its server-to-server scheduler secrets.

## Credentials and API scope

- System-generated Bybit HMAC-SHA256 API keys are supported.
- Enable only the P2P read-only permission.
- Credentials are encrypted on the server using AES-256-GCM and BYBIT_P2P_ENCRYPTION_KEY.
- Preview and Production must have separate, independently generated BYBIT_P2P_ENCRYPTION_KEY values.
- The scheduler uses a separate BYBIT_P2P_SCHEDULER_SECRET; it is not an exchange credential.
- No create-order, payment, release, transfer or withdrawal endpoint is called.
- Current endpoint: https://api.bybit.com/v5/p2p/order/simplifyList.
- The API host can be changed only through server-side BYBIT_P2P_API_BASE_URL and must match the allowlist in lib/bybit-p2p.js.

## Order mapping and safeguards

Bybit completed orders use status 50. side maps 0 to Compra and 1 to Venta. amount is the fiat total, price is fiat per token, and notifyTokenQuantity is the crypto quantity. These values are stored separately.

The Bybit order-list schema does not identify the fee currency. The raw fee is retained as sourceFee, while fee=0 and fee_currency=null prevent an unverified fee from distorting calculated results.
